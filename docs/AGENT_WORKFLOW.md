# 复杂任务交接与多 Agent 协作手册（AGENT WORKFLOW）

> **何时阅读**：仅在需要创建独立候选工作树修改仓库、跨多轮对话留存任务交接记录，或将复杂任务拆分派发给多个子 Agent 并行/复核时阅读。日常问答与简单任务无需阅读。

---

## 一、候选工作树与分级验证标准

### 1. 创建独立候选工作树
修改仓库文件时，保持主分支检出目录干净，从 `master` 开独立工作树或特性分支施工：

```bash
git worktree add -b <分支名> ../worktrees/<日期-主题> master
```

（若涉及大体积编译产物，可将构建缓存放到仓库外的独立临时目录，避免污染工作区。）

### 2. 按改动风险分级验证
复用仍然有效的证据，验证力度与改动风险匹配，达到验收标准后及时收尾：

| 改了什么 | 最低验证要求 |
| --- | --- |
| **文档或规则** | 核对 `git diff`；所有链接与路径真实可达；各文档间无规则冲突 |
| **后端功能或缺陷** | 验证用户可感知的行为与受影响接口；修缺陷须先复现，并补上能拦住回归的自动化测试 |
| **前端页面或交互** | 通过 `check:i18n` / `typecheck` / `lint:check` / 单测 / `build`，并用本地 Playwright 在真实浏览器操作页面与看图验收 |
| **权限、凭据、账务、迁移、上线** | 动手前写清不变量与异常恢复方案；最终候选须安排独立只读复核 |

记录验证时写清：针对哪个提交或候选、实际跑了什么、结果怎样、哪些边界未覆盖（模拟或本地编译不能冒充真实线上验收）。

## 二、跨对话任务交接记录（`HANDOFF.md`）

- **何时写**：多步骤、长耗时或可能跨对话继续的任务，在被 Git 忽略的 `.agent-logs/<日期-任务>/HANDOFF.md` 维护当前状态（到关键阶段、计划变更或暂停时更新）。
- **写什么**：用户原话、范围、已完成与未完成项、验证结果与证据路径、仍在运行的后台进程、风险、下一步与更新时间。
- **防膨胀铁律**：**严禁把整套前后端源码快照或 `node_modules` 拷贝进 `.agent-logs/`**，严禁把任何敏感凭据或生产数据写入日志。
- **如何接手**：`.agent-logs/` 被 Git 忽略；接手时读完对应任务的 `HANDOFF.md` 后，务必重新核对实时 Git 状态、进程与测试结果，不盲信旧记录。

## 三、派发子 Agent 规范（仅并行或独立复核时使用）

### 1. 什么时候派发
- 只有在**并行能明显节省等待时间**，或**高风险改动需要不受实现者先入为主影响的独立只读复核**时才派发。
- 能用本地脚本批量完成的不派；同一问题不重复派给多个 Agent（交叉核对除外）。

### 2. 单写者与隔离原则
- **同一文件或同一可写运行资源，同一时刻只能有一个负责人**：除源码外，还包括 `HANDOFF.md`、锁文件、依赖安装、`ent/` 生成代码、端口、本地测试数据库与 `backend/internal/web/dist`。只读审查不占写入名额。
- **先定公共契约再分头实现**：接口、类型、Schema 与共享配置先由一人敲定，变更须同步所有受影响方。
- **主 Agent 承担最终核验责任**：子 Agent 报告“已完成”仅作汇报，主 Agent 必须亲自核对最终 `diff` 与验证证据；独立复核者只给原始需求、最终差异、测试证据和已知风险，不预先透露实现者结论。
