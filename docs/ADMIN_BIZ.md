# 运营与管理后台领域手册（ADMIN & BIZ）

> **何时阅读**：仅在协助操作管理后台、配置账号/分组/渠道定价、排查模型不可用或倍率异常、处理充值/兑换码/返利/退款、起草或发布站内公告与运营活动时阅读。纯代码重构或纯基础设施任务无需阅读。

---

## 一、核心业务对象与计费速查

### 1. 后台运转的 4 个核心对象
1. **账号管理（`/admin/accounts`）**：接入上游 API Key、OAuth、Setup Token 等真实凭证并绑定出口代理。
2. **分组管理（`/admin/groups`）**：将同平台账号归组，统一设定平台类型（创建后不可改）、默认倍率、余额/订阅属性、模型白名单与高峰/媒体独立倍率。
3. **渠道管理（`/admin/channels/pricing` & `/admin/channels/monitor`）**：配置渠道级模型单价、分时段定价，以及 V1 主动探活 / V2 被动流量监控。
4. **用户与 API 密钥（`/admin/users` & 用户端 `/keys`）**：每把用户 API Key 只绑定一个分组，仅可调用该分组允许的协议与模型。

### 2. 定价与倍率命中优先级（调价防错必看）
- **1:1 等值铁律**：站内所有余额、限额、套餐与单价以 USD（`$`）计量，与人民币严格 `1:1` 等值（充 `¥1` = 到账 `$1`）。后台「支付设置」中 `balance_recharge_multiplier` 必须保持默认 `1`，`subscription_usd_to_cny_rate` 保持默认 `0`，**切勿误填外汇汇率**。
- **基础单价命中顺序（命中即止）**：`分组模型价卡` > `渠道模型价卡（含分时段/工作日限定）` > `LiteLLM 动态目录` > `内置兜底价卡`。
- **客户实付倍率顺序**：`用户个人专属分组倍率（/admin/users）` > `分组默认 rate_multiplier` > `系统默认 1.0`。（另注意区分仅对订阅分组文本生效的高峰倍率、图片/视频独立倍率，以及 Fast / Ultra Fast / Flex 服务档位乘数，入账精度为 8 位小数 USD）。

## 二、高频操作防踩坑清单

1. **严禁跨平台混选批量修改账号（丢映射高发坑）**：
   - 在 `/admin/accounts` 批量编辑账号时，**绝不要同时勾选不同平台的账号**（例如混选 OpenAI 与 Gemini/Antigravity），否则模型白名单与关键映射会被跨平台策略覆盖，导致客户端调用报 `Service temporarily unavailable`（但后台按钮单点测试看似正常）。
   - 务必按平台分组筛选后再批量操作；若不慎丢映射，优先手动批量补回显式透传映射。
2. **分清「兑换码」与「优惠码」**：
   - 给老用户充余额、加并发、送订阅 → 去 **兑换码（`/admin/redeem`）** 生成，用户在控制台 `/redeem` 兑换。
   - 给新用户发注册赠金 → 去 **优惠码（`/admin/promo-codes`）** 生成，**仅限新用户在注册页填写**。
3. **订单退款与邀请返利口径**：
   - 余额订单退款时，支付渠道实退现金按 `pay_amount × 退款 USD / order.amount` 等比折算，防止把满赠额度多退成现金。
   - 邀请返利仅按实付充值本金（扣除满赠额）或订阅实付计提；用户端仅支持一键划转入站内余额，不设自助现金提现接口。
4. **高影响后台开关**：
   - 删除分组或改分组默认倍率会立即影响存量 API Key（删组直接报 `403 GROUP_DELETED`）；
   - 开启邮箱验证或改邮箱后缀白名单前，先在「邮件设置」实测发信成功；
   - 更新「登录条款」日期会触发全站用户下次登录重新弹窗确认。

## 三、站内公告与官方社群播报规范

1. **上线前必须先交站点负责人过目**：在 `/admin/announcements` 发布任何公告前，必须先将完整**标题、正文文案、配图/海报、通知弹窗模式、受众范围与生效时间**发给负责人确认；未经批准前最多只能存为草稿（`draft`），**严禁未审直接设为 `active`**。
2. **正式上线同步社群播报**：公告获批正式发布时，按站点私有运营配置同步推送到官方用户社群频道，避免站内与社群信息不同步。
