## 1. 先懂整体架构：从上游到用户调用的 4 个核心对象

在 Gabugu 后台里，一切业务都围绕 4 个对象运转：

1. **账号管理（`/admin/accounts`）**：接入上游 AI 服务商凭证（官方 API Key、OAuth、Setup Token、第三方兼容中转端点等），负责真正向上游发请求。
2. **分组管理（`/admin/groups`）**：把同一平台的上游账号归成「分组」，统一定义该分组的**平台类型、计费倍率、订阅/余额属性、模型白名单、高峰倍率、长上下文策略、是否专属**。
3. **渠道管理（`/admin/channels/pricing` & `/admin/channels/monitor`）**：管理渠道级自定义模型单价/分时段定价，以及 V1 主动探测 / V2 被动流量监控。
4. **用户与 API 密钥（`/admin/users` & 用户端 `/keys`）**：用户创建绑定到某个分组的 API 密钥；调用时网关先鉴权与预检余额/订阅额度，再按分组调度可用账号并实时入账。

**重要原则**：
- 站内所有**余额、Key 限额、订阅额度、模型单价**均以 `$`（USD 标价）计量；**Gabugu 采用 1:1 等值口径（美元等于人民币、人民币等于美元，充 1 元人民币 = `$1` 站内额度，不做外汇汇率折算）**。
- 每条 API 密钥只绑定一个分组；用户只能调用该分组支持的协议与模型。

## 3. 系统设置（`/admin/settings`）9 个标签页速查

1. **通用设置（`general`）**：站点名称、副标题、Logo、客服联系方式（`contact_info`）、对外 API 基础地址（`api_base_url`）、外链文档（`doc_url`）、自定义首页内容、自定义侧栏菜单。
2. **登录条款（`agreement`）**：维护登录/注册前展示的法律条款 Markdown（当前生产线上为 4 份：`terms` 服务条款、`usage-policy` 使用政策、`privacy-policy` 隐私政策、`recharge-refund` 充值与退款规则）、展示模式（弹窗/勾选）与更新日期。
3. **功能开关（`features`）**：
   - **模型广场（Model Plaza）**：控制是否开启 `/model-plaza`、是否强制登录可见，以及顶部的**全局价格说明 Markdown**。
   - **可用渠道（Available Channels）**：旧版聚合渠道页开关（线上通常保持关闭，以模型广场为主）。
   - **渠道监控（Channel Monitor）**：总开关 + `V1 主动探测` / `V2 被动监控` 二选一 + 隐藏吞吐/排行开关。
   - **站点类型（Site Billing Mode）**：`充值 & 订阅`、`仅充值`、`仅订阅`。
   - **插件管理 / 风控中心 / 邀请返利 / MCP 接入**等模块开关。
4. **安全与认证（`security`）**：
   - **Admin Access Keys（管理员接口密钥）**：支持最小权限分发；旧全权密钥折叠收起。注意：**管理员 Access Key 创建后仅显示一次**（与普通用户 API Key 不同）。
   - 注册开关、邮箱验证开关、**注册邮箱后缀白名单**（线上白名单含 `@qq.com`、`@gmail.com` 等 7 个主流域名）、非白名单单域名限注（`registration_email_domain_quota_enabled`）、邮箱黑名单、人机验证（Turnstile / 腾讯 / 阿里云）、OAuth（LinuxDo / 微信 / OIDC / GitHub / Google）、Passkey 与 2FA 策略。
5. **用户默认值（`users`）**：新用户默认并发数、默认注册余额、默认分配的公开分组等。
6. **网关服务（`gateway`）**：529 过载冷却、上游错误透传规则、重试与超时策略、流式/异步图片保活参数等。
7. **支付设置（`payment`）**：总开关、金额上下限、待支付上限、手续费率、充值比例（`balance_recharge_multiplier`，**本站按 1:1 保持默认 `1`**）、订阅换算项（`subscription_usd_to_cny_rate`，**本站按 1:1 保持默认 `0`**）、**充值满赠/折扣阶梯**与活动 Markdown、帮助文案与图片、各支付服务商实例管理（EasyPay / 支付宝直连 / 微信直连 / Stripe / Airwallex）。详见 [PAYMENT_CN.md](PAYMENT_CN.md)。
8. **邮件设置（`email`）**：SMTP 发信配置、发件人名称与测试发送（用于注册验证码、密码重置和余额不足提醒）。
9. **数据备份（`backup`）**：PostgreSQL S3 自动备份配置，以及**异步生图对象存储（Async image object storage）**配置（详见 [POSTGRES_BACKUP.md](POSTGRES_BACKUP.md) 与 [ASYNC_IMAGE_TASKS.md](ASYNC_IMAGE_TASKS.md)）。

## 4. 计费与定价口径（必读，避免调价踩坑）

### 4.1 基础单价解析优先级
单次请求查找模型基础单价时，按以下严格顺序命中即止：
1. **分组模型价卡**（优先级最高；注：分组 Token 价卡覆盖平价/首档，长上下文阶梯仍由官方预设 + 分组开关控制）
2. **渠道模型价卡**（`/admin/channels/pricing`，支持分时段价格 `ChannelTimePricing` 与工作日限定 `WeekdaysOnly`）
3. **LiteLLM 动态目录价卡**
4. **内置兜底价卡**

### 4.2 客户实付倍率优先级
- **基础客户倍率**：**用户个人专属分组倍率（`/admin/users` 编辑，直接覆盖分组默认倍率） > 分组默认 `rate_multiplier` > 系统默认 `1.0`**。
- **订阅高峰倍率**：仅对**订阅型分组**（`group_type = subscription`）的**文本 Token**在系统时区高峰窗口内叠加生效；普通余额分组不可开启，且不作用于图片/视频/搜索/音频。
- **图片 / 视频独立倍率**：分组可勾选独立倍率；未勾选时沿用基础客户倍率（不含高峰倍率）。
- **服务档位与特殊加价**：
  - `Fast (priority)` 默认 `2.0x`（`gpt-5.5` 为 `2.5x`，Gemini 4 系列为 `1.8x`）；分组开启 `FreeOpenAIFast` 时 OpenAI `priority` 按 Standard 计客户实付。
  - `Ultra Fast` 仅支持 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-6.2-sol`、`gpt-6.2-astra`（`gpt-6.2-*` 在太平洋时间 2027-03-01 前为 `3x`，之后自动切 `6x`；其余两款固定 `6x`）。
  - `Flex` 默认 `0.5x`。
  - **思考深度倍率**：分组/渠道价卡可为特定 `reasoning_effort` 配置额外乘数。
  - **DeepSeek 官方默认价卡**：北京时间工作日 `09:00–12:00` 与 `14:00–18:00` 按 `2.0x` 高峰计费，周末全天 `1.0x`。
  - **Token 限时活动折扣**：仅作用于余额分组的纯文本 Token（不含图片/视频/搜索/缓存存储费），按请求开始时间 `PricingAt` 锁定。
- **入账精度**：统一四舍五入至 **8 位小数 USD**（`NUMERIC(20,8)`）。

### 4.3 订阅配额重置规则
- 订阅首次发起请求时**懒激活**窗口：日窗口锚点为系统时区（`Asia/Shanghai`）当日 `00:00`，周/月窗口锚点为首次使用精确时间。
- **日重置**：系统时区次日 `00:00`（例外：1 天期订阅为一次性日额度，不跨日重置）。
- **周 / 月重置**：从首次使用时间起固定滚动 **7×24h（168h）** / **30×24h（720h）**，且不超过到期时间 `ExpiresAt`。
- **续费**：活跃期续费只顺延到期时间、不清零已用额度；过期后续费重新开启周期。

### 4.4 邀请返利规则
- 余额充值订单返利仅按**实付充值本金（扣除充值赠送额）**计提；订阅订单按订单金额计提；正数余额兑换码触发返利（支付系统内部自动兑换码不重复计提）；管理员手工加余额默认不返利（除非开启 `affiliate_admin_recharge_enabled`）。
- 用户端仅支持将已解冻的可用返利额度**全部一键划转至账户余额**（无自助现金提现接口）；如需线下现金打款，由管理员在后台手工核销并入账提取记录。

## 5. 标准业务操作流程（SOP）

### 5.1 新上线一个模型分组
1. 进入 **分组管理（`/admin/groups`）** → 点击「创建分组」，选定平台（创建后不可更改）、设置计费倍率与公开/专属属性。
2. 进入 **账号管理（`/admin/accounts`）** → 添加同平台的上游账号并勾选该分组 → 点击行内「测试」确认通路正常。
3. 如需自定义单价或分时段定价，前往 **渠道管理 → 渠道定价（`/admin/channels/pricing`）** 配置并核对。
4. 打开 **模型广场（`/model-plaza?embedded=1`）** 核对前端展示的模型列表、实际单价与参考标准价是否符合预期。
5. 用管理员个人区 `/keys` 创建一条绑定该分组的测试密钥，验证一次真实调用并在 `/admin/usage` 核对账单与上游成本。

### 5.2 给用户发余额、并发、订阅或优惠码
- **手工调整某用户余额/并发**：进入 **用户管理（`/admin/users`）** → 找到用户 → 调整余额或编辑并发 / 专属倍率。
- **发放兑换码（充余额 / 加并发 / 送订阅）**：进入 **兑换码（`/admin/redeem`）** 生成，发给用户在控制台「兑换（`/redeem`）」页面使用。
- **发放新用户注册赠金**：进入 **优惠码（`/admin/promo-codes`）** 生成，告知新用户在**注册页面**填写（不可在「兑换」页面使用）。

### 5.3 处理订单未到账与退款申请
1. 进入 **订单管理（`/admin/orders`）**，按订单号或用户邮箱检索订单状态。
2. 若状态停留在 `PAID` 或 `FAILED`，确认第三方支付渠道确实收款后使用后台补单/重试入账功能。
3. 若收到退款申请（或用户邮件联系）：先区分退款入口与订单类型——用户自助仅支持余额订单整单申请（要求当前 USD 余额 ≥ 该订单入账总额 `order.amount`），订阅订单不可自助申请；管理员后台则同时支持**余额订单**（按入账 USD 金额发起全额/部分退款，可选是否扣减余额或 `force` 强制退款，支付渠道实退金额按 `pay_amount × 退款 USD / order.amount` 等比折算，确保赠送额度不多退现金）与**订阅订单**（按需扣减订阅天数或撤销订阅）。请结合 `recharge-refund` 条款审核后执行。

## 6. 高风险操作核对清单（执行前必停顿确认）

- **修改分组默认倍率或删除分组**：会立即影响该分组下所有存量 API 密钥的计费或直接导致调用报 `403 GROUP_DELETED`。
- **禁用或删除高流量上游账号**：先确认同分组还有其他健康账号可接管流量。
- **修改「支付设置」里的充值比例 / 满赠阶梯 / 服务商密钥**：Gabugu 采用 **1:1 等值计价（1 元人民币 = `$1` 站内额度）**，`balance_recharge_multiplier` 保持默认 `1`、`subscription_usd_to_cny_rate` 保持默认 `0`，切勿误填外汇汇率值；调整满赠/折扣阶梯或服务商密钥后立即打开 `/purchase` 核对金额预览。
- **修改「登录条款」与版本日期**：更新日期变化会触发全站用户下次登录时重新同意条款。
- **修改邮箱后缀白名单或开启邮箱验证**：保存前先在 **邮件设置** 测试发信成功，避免新用户收不到验证码。
- **关闭模型广场或修改「站点类型」**：会影响普通用户侧栏和购买页可见性，调整后请用普通账号视角抽查一次。
- **站内公告发布规范**：在 `更多 → 公告`（`/admin/announcements`）创建或上线任何中转站公告前，必须先将公告完整文案、配图/海报、弹窗模式、受众范围与生效时间交给站长（用户）过目确认，未获确认前只能保存为草稿（`draft`），不得直接设为 `active`。公告经确认并正式发布时，按站点运营规范同步推送到官方用户社群频道。
