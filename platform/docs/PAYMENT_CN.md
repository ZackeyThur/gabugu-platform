# 内置支付系统配置指南

Gabugu（基于 Sub2API v0.2.23）内置完整的支付与收银台系统，支持**余额充值**与**订阅套餐购买/续费**，无需额外部署独立支付服务。

> **GABUGU 站点汇率约定**：本站美元额度与人民币采用 **1:1 汇率**，即用户充值 `¥1` 等于到账 `$1` 账户额度（`balance_recharge_multiplier = 1`）。

## 支持的支付服务商与方式

| 服务商 | 支持的支付方式 | 适用场景与说明 |
| --- | --- | --- |
| **EasyPay（易支付）** | 支付宝、微信支付 | 兼容标准易支付协议的第三方聚合渠道 |
| **支付宝直连（Alipay Direct）** | 电脑端扫码（当面付优先，网站支付回退）、手机端拉起支付宝 | 直连支付宝开放平台，无聚合中介抽成 |
| **微信支付直连（WeChat Pay Direct）** | Native 扫码、H5 支付、公众号 JSAPI（微信内） | 直连微信支付 APIv3，按客户端环境自动路由 |
| **Stripe** | 银行卡、支付宝、微信支付、Link 等 | 国际收单，支持多币种（USD / CNY / EUR 等） |
| **Airwallex（空中云汇）** | 国际卡 / 多币种收单 | 内嵌 Airwallex 组件收银台，支持多币种结算 |

> **前端展示规则**：支付宝直连与易支付支付宝、微信直连与易支付微信可在后台同时保存实例，但用户端收银台始终只暴露统一的「支付宝」「微信支付」入口，由管理员在支付设置中为每个可见方式指定唯一启用来源（直连或易支付），避免向用户暴露底层支付服务商品牌。

## 快速开始

1. 登录管理员后台，进入 **系统设置 → 支付设置**（`/admin/settings`）
2. 开启 **启用支付**，并在 **系统设置 → 功能开关 → 站点类型** 选择购买模式（`充值 & 订阅`、`仅充值` 或 `仅订阅`）
3. 配置基础参数（单笔限额、日限额、订单超时、待支付上限与手续费率；Gabugu 采用 1:1 计价，比例项保持默认即可）
4. 在 **支付服务商管理** 中添加至少一个已启用的服务商实例（如支付宝直连、微信直连、EasyPay、Stripe 或 Airwallex）
5. 如需售卖订阅套餐，前往 **订单管理 → 订阅套餐**（`/admin/orders/plans`）创建并上架套餐
6. 用普通用户账号打开 `/purchase`，确认币种符号、到账金额预览和支付按钮显示正常

## 系统设置与计价规则

在 **系统设置 → 支付设置** 中配置以下核心项：

### 基础参数

| 设置项 | 说明 | 默认值 |
| --- | --- | --- |
| **启用支付** | 支付系统总开关 | 关闭 |
| **商品名称前缀 / 后缀** | 显示在第三方收银台的订单标题 | - |
| **单笔最小 / 最大金额** | 限制用户单笔支付金额（按支付渠道币种计；最大留空不限） | 最小 1 |
| **用户每日限额** | 单个用户每日累计充值上限（留空不限） | 不限 |
| **订单超时时间** | 未支付订单自动过期时间（分钟，最低 1） | 30 |
| **最大待支付订单数** | 单个用户同时允许的 `PENDING` 订单数 | 3 |
| **负载均衡策略** | 多实例调度策略：`轮询（Round Robin）` 或 `最小日交易额（Least Amount）` | 轮询 |

### 币种、等值规则与手续费

- **站内计价单位与 1:1 口径**：用户账户余额、API 密钥额度、订阅限额与模型单价以 `$`（USD 标价）显示；**Gabugu 现网采用 1:1 等值口径（充 1 元人民币 = `$1` 站内额度，不做外汇汇率折算）**。
- **支付币种**：默认网关支付币种为 `CNY`（人民币，`¥`）；Stripe / Airwallex 实例可单独配置 `USD`、`EUR`、`HKD` 等币种。前端金额输入框与确认支付按钮会自动匹配所选方式的支付币种符号。
- **余额充值比例（`balance_recharge_multiplier`，可选高级项）**：
  - 公式：`到账基础额度 = round2(输入支付金额 × 比例)`，**默认 `1.0`（Gabugu 保持默认 `1.0`，无需改动）**。
  - 仅在配置为非 `1` 时，用户端收银台才会额外展示换算比例行；为 `1` 时保持界面简洁不展示。
- **支付手续费（`recharge_fee_rate`）**：
  - 在支付基数之上按百分比计算，向上取整至该币种最小支付单位：`实付金额 = 支付基数 + ceil(支付基数 × 手续费率 / 100)`。
- **订阅订单换算（`subscription_usd_to_cny_rate`，可选高级项）**：
  - **默认 `0`（不换算，直接按套餐标价 1:1 结算；Gabugu 保持默认 `0`，无需改动）**；仅当设为 `> 0` 且当前通道为 `CNY` 时才乘该系数。

### 取消频控与帮助信息

- **取消频率限制**：支持滑动/固定时间窗口，限制用户在窗口内反复下单后取消订单的次数。
- **帮助图片与帮助文案**：支持上传图片与编写 Markdown 文案，展示在用户充值页底部（建议写明到账币种、客服邮箱与未到账排查方式）。

## 充值优惠阶梯（满赠 / 折扣）

在 **支付设置** 中可配置多档充值优惠阶梯（按单笔支付金额命中满足条件的最高档位）与顶部活动公告 Markdown：

- **满赠模式（`bonus`）**：用户按原金额支付，到账余额额外增加赠送 USD：`赠送额 = round2(到账基础 USD × 赠送百分比)`；到账总额 = 基础 USD + 赠送额。
- **折扣模式（`discount`）**：用户实付金额按比例立减，到账 USD 保持原档位基础额。
- **返利基数说明**：余额充值触发邀请返利时，仅按**实付充值本金（扣除赠送额）**计算，赠送部分不计提返利。

## 订阅套餐配置

在 **订单管理 → 订阅套餐**（`/admin/orders/plans`）中管理可售卖的订阅套餐：

- 每个套餐绑定一个**订阅型分组**，继承该分组的平台、模型范围、计费倍率、高峰倍率与日/周/月 USD 限额。
- 支持配置套餐名称、原价（划线价）、售价、有效期（天/周/月）、特性列表、排序与上架开关（`for_sale`）。
- 用户在 `/purchase` 切换到「订阅」标签页即可选购或对当前有效订阅发起续费（活跃期续费顺延到期时间，过期后续费重开计费窗口）。

## 支付服务商配置

在 **支付设置 → 服务商管理 → 添加服务商** 中选择对应类型并填写凭证。系统会根据站点域名自动生成回调（Notify / Return）地址：

| 商户 ID（PID） | 易支付商户号 | 是 |
| 商户密钥（PKey） | 易支付签名密钥 | 是 |
| API 地址 | 易支付接口基础地址 | 是 |
| 支付宝 / 微信通道 ID | 指定子通道编号（可选） | 否 |

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| AppID | 支付宝开放平台应用 ID | 是 |
| 应用私钥 | RSA2 应用私钥 | 是 |
| 支付宝公钥 | 支付宝平台公钥 | 是 |

### 微信支付直连（WeChat Pay Direct）
基于微信支付 APIv3，自动适配电脑端 Native 扫码、手机外部浏览器 H5、微信内公众号 JSAPI。
| 参数 | 说明 | 必填 |
| --- | --- | --- |
| AppID | 关联小程序/公众号 AppID | 是 |
| 商户号（MchID） | 微信支付商户号 | 是 |
| 商户 API 私钥 | PEM 格式商户私钥 | 是 |
| APIv3 密钥 | 32 字节 APIv3 密钥 | 是 |
| 微信支付公钥与公钥 ID | PEM 格式平台公钥及对应 ID | 是 |
| 商户证书序列号 | 商户 API 证书序列号 | 是 |

### Stripe
| 参数 | 说明 | 必填 |

## 服务商实例管理与负载均衡

支持为同一类型创建多个独立实例，用于容灾分流与风控：
- **独立限额**：单实例可设最小金额、最大金额与每日交易上限；超出上限自动跳过。
- **独立开关与排序**：支持单独启停实例与拖拽排序。
- **退款权限开关（`allow_user_refund`）**：可按实例控制是否允许用户对已完成的余额订单发起自助退款申请。

## 支付流程、订单状态与退款

### 主链路
1. 用户选择充值金额或订阅套餐与支付方式 → 后端校验限额/待支付上限/换算规则，创建 `PENDING` 订单并路由服务商实例。
2. 用户完成支付 → 收到第三方 Webhook 并验签与校验金额（容差 `0.01` 或半个最小货币单位）→ 订单进入 `PAID`（支持超时后 5 分钟宽限期内捞回延迟回调）。
3. 后台履约器加 5 分钟租约将订单置为 `RECHARGING`，原子入账 USD 余额或开通/续期订阅 → 订单置为 `COMPLETED`。
4. 后台任务每 60 秒扫描即将超时的 `PENDING` 订单，先向支付渠道主动反查状态，已付款则自动补单，未付款再标记 `EXPIRED`。

### 订单状态速查

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待支付 |
| `PAID` | 已收到支付确认，等待入账 |
| `RECHARGING` | 正在执行余额/订阅原子入账 |
| `COMPLETED` | 支付并入账完成 |
| `EXPIRED` | 超时未支付自动关闭 |
| `CANCELLED` | 用户主动取消 |
| `FAILED` | 入账异常，管理员可在订单列表重试补单 |
| `REFUND_REQUESTED` | 用户已提交退款申请，待管理员审核 |
| `REFUNDING` / `REFUND_PENDING` | 退款处理中 / 等待渠道异步确认 |
| `REFUNDED` / `PARTIALLY_REFUNDED` | 已全额退款 / 已部分退款 |
| `REFUND_FAILED` | 退款失败，需管理员排查重试 |

### 退款口径
- **用户自助申请退款（`RequestRefund`）**：仅支持**余额充值订单**（订阅套餐订单会返回 `INVALID_ORDER_TYPE`）；且仅支持整单申请，要求用户当前 USD 余额不少于该订单入账总额（`order.amount`，含赠金）。
- **管理员后台退款（`PrepareRefund` / `ExecuteRefund`）**：
  - **余额订单**：支持按**入账 USD 金额**发起全额或部分退款（不超过该订单剩余可退 USD `order.amount`），管理员可选择是否扣减余额（`deduct_balance`），余额不足时可启用强制退款（`force=true`）。
  - **订阅订单**：管理员可在后台按情况退款，支持扣减订阅天数（`subscription_days`）或撤销订阅。
  - **渠道实退折算**：实际退回支付渠道原币种金额按 `pay_amount × (退款 USD / order.amount)` 等比折算（全额退款上限为 `pay_amount`），保证充值赠送额度不会被多退现金。

## 从旧外部支付（Sub2ApiPay）迁移

如早期使用外部独立部署的 Sub2ApiPay，可直接迁移至当前内置支付：

| 对比项 | 旧外部支付（Sub2ApiPay） | 当前内置支付（v0.2.23） |
| --- | --- | --- |
| 部署方式 | 独立 Next.js + PostgreSQL 服务 | 内置在主后端，无额外服务 |
| 支付渠道 | 易支付 / 支付宝 / 微信 / Stripe | 易支付 / 支付宝直连 / 微信直连 / Stripe / Airwallex |
| 订阅套餐 | 支持 | **已完整支持**（购买、续费、独立汇率） |
| 充值优惠 | 外部配置 | **内置支持**（满赠/折扣阶梯、换算比例） |
| 入账机制 | 外部调 Admin API | 内部原子事务 + 自动超时反查补单 |
| 订单与退款管理 | 独立管理后台 | 集成在 **订单管理（`/admin/orders`）** |

迁移步骤：在 **系统设置 → 支付设置** 录入相同商户凭证 → 将支付平台回调切换至新 Webhook 路径 → 验证一笔小额测试订单正常入账 → 保留旧系统只读查账一段时间后下线。
